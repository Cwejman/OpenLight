**Rebirth, round eight — projected vs sovereign (render-injection understood).** The author's React proposal, clarified, superseded round seven's iframe-vs-React framing: the program stays a program to the engine; its *render output* crosses into the embedder — code and credential never do. Folded as leading candidate (programs.md §3.5): **two embedding grades** — *projected* (default: pure render = f(scope), executed by a host-side projector that resolves scope first and renders once with data in hand; UI-as-data injected at the slot; interaction via declarative intents executed under the citizen's engine identity) and *sovereign* (exception: confidential interaction like the composer, live execution, untrusted code — realm boundary with per-slot identity). Cost collapses — projected citizens are render calls on commit, not realms or resident processes; minimized-forms-as-data was this grade's first special case. Open: UI-as-data shape (neutral vs React-element), purity enforcement (read-only handle, intents as only effect channel), `projection` as a third runtime kind — resonant with projection-as-one-primitive.

**Rebirth, round seven — library vs citizen; arrangement ownership opened.** The iframe-vs-React question dissolved by definition: in-realm composition is *library use inside one program* (always allowed, never citizenship); a citizen is another program, and programhood needs a realm boundary to be enforced rather than advisory — so expanded citizens are sandboxed iframes (DOM-streams later), React is the compromise, not the iframe. New: **minimized forms are data, not surface** — a minimized citizen writes its minimal living state into its frame and the widget stack renders it from the field (controls are chunk writes); only expanded citizens cost a realm, and the widget stack is owned by no one. Ground-owns-slots demoted from proposal to *open*: candidate split is a shared arrangement layer for medium-independent placement (uniform across views, person-governed) with grounds *offering* medium-dependent anchors (reply-at-message) into it — needs examples beyond the conversation to settle; converse arranging itself first harms nothing.

**Rebirth, round six — surfaces embed surfaces (requirement settled; slots proposed).** Author grounded the peer inversion's missing half: composition can't belong solely to the host's split — a surface must render other programs within its own layout (the composer pinned at the thread's scroll-bottom, shrinking to a widget when scrolled away; an email reply rendering *at the message* via its reply verb, not in a bottom split). Requirement settled; mechanism proposed and marked leading-candidate in programs.md §3.5: **slots** — embedder declares in-flow / pinned / widget positions and governs geometry, never content; every embedded citizen stays its own process (own boundary, own commit attribution); ground citizen provides its medium's slots, host provides fallbacks; respect gains two rules (embedder can't observe embedded content; embedded can't escape its slot). v0.1 material candidate: sandboxed iframes with **per-slot transport identity** — new demand in §6 (host.md + sdk.md), beside the ensemble-tile demand.
