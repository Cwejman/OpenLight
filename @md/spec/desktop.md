# Desktop — the pilot's environment module

`desktop/` — a store like any other, depended on from the home's toml ([`chassis.md`](chassis.md)). It ships the pilot's configuration and its environment components; nothing in it is mechanism — everything below is instances of contracts [`view.md`](view.md) and [`chassis.md`](chassis.md) declare.

- **the entry** — two layers (content, overlay), two reservations (the secondary gesture → the overlay place; the approval chord → the consent place), the surface config (faces, `FrameBox`).

- **the shell — the simple tiler** [tabs and sidebar out of the pilot shell: R; the verb set steward-drafted: P]. `desktop/shell : view/component { accepts: [ ref(session) ] }` realized **as a template** placing `$session.root` — a tree of `split` and content mounts; the arrangement chunks shrink to `session { root?: ref(view/mount) }` (`tab` dies with the tab strip; the old tile tree is superseded whole). The tiler is verbs and one gesture, no mechanism of its own: **split** — a command verb from the match, reached by the secondary gesture (who declares it is unpicked [O] — `actions` sit on programs/components at two scopes), wrapping the target mount in a new `split { direction, [target, new] }`, the new pane filled by the defaults table's last resort until content is chosen; **close** — the ruled body edit, removing the mount from its parent's list, a single-child `split` collapsing into its child (the verb's own normalization); **resize** — the divider is the split implementation's own pointer interaction (the ordinary gesture belongs to the component in use), committing `ratio`; **move/swap** — post-pilot, riding the drag layer, and WYSIWYG rearrangement with it; the tiler needs nothing from that layer to be usable. With tabs gone the shell is nearly transparent — its remaining duty is resolving *which* session.

- **`sidebar`** — out of the pilot shell; remains a declared component in the module, mountable like any content. The session rendered as itself, **work only** — processes mean work (whether mounts show too [O]): life before rest, then recency; running rises as a live card, terminal falls flat; a draft rests as unsent thought; the context menu carries each item's state verbs (jump, inspect, terminate — explicit, cascades —, re-run, review changes, hide — a `relates` onto a session-local `hidden`; the sidebar reads `[session] − [hidden]`). Clearing is non-destructive; processes *are* the history.

- **the session — minor state of the pilot desktop module [R — 2026-08-20].** Not an engine concept (the engine's `launch` owner is configured — [`engine.md`](engine.md)). Two duties earn the chunk: the **writable indirection** — the entry is shipped read-only, so the live arrangement needs a writable home, and `$session.root` is that seam — and the **work group** — launched processes owned by the session, so kill cascades and the sidebar has a "work" to render. `session { root }` sits in the store it was opened for.

- **`projects`** — a component over `[engine/attached]` (its shape [O]): discovery as an expression over configured search paths (`~/git/*/.ol`) through `filesystem`; its verbs (`attach` with a mode, `detach`) come from the match, as any menu's do. **Project management is attach management, in the desktop, never in a binary.** "Current project" is the session's store — a session sits in the store it was opened for.
