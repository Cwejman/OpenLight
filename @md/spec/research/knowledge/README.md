# The knowledge arc

How knowledge should be structured, so that what one person understands reaches whoever needs it next, is not cracked. This arc is the search for it. It has produced enough to be used, and this page says what stands and in what order to take it.

## 1. The code

The code is the law, and the place to start. It turns written knowledge into a medium, one that joins us to what we know and to each other, so that keeping it in order stops being a job of its own: you take part in it, and you add to it. It gives what knowledge is made of, the gradient it is laid by, and the few principles that follow, and one reading of it leaves you able to write under it.

[the level beneath](code.md)

## 2. The proof of concept

The proof of concept is the code put to use where we stand now, in the simplest medium there is: markdown files in folders, tracked in git, read by people and by sessions bootstrapped against them. It is what can be done with the code before any medium beyond that is built, and it grows as the work does.

[the level beneath](poc/README.md)

## 3. The study

The study is where all of this is being found, and where it is still owed. It is the search for how knowledge is best structured, for people and AI alike, run as a series of labs on one shared corpus, a bounded set of research reports from an August web sweep. Each lab rewrites the same material under an edition of the code and reads the result cold.

The grounds are what it produces, and in time the study retires into them. Its entry is the notebook. It holds where the search stands, what it still owes, and what the running of it has taught.

[the level beneath](study/README.md)

## 4. The ideas

Beside the code stand the author's ideas: positions on how a model and a harness should be offered, the domains the shape reaches into, and questions it raises on the way. They are held open. None of them is law, and nothing in the code depends on them.
