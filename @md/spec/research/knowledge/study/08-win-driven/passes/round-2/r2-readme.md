# Clean-room pass: README vs ontology

Ground: `README.md` then `@md/spec/research/knowledge/study/08-win-driven/ontology.md`, nothing else. Declared divergences excluded: kernel = the tree's engine; engine = one citizen among many; substrate below the kernel. Where a finding is a downstream consequence of one of those three it is marked *(downstream of declared #n)* and counted separately.

## 1. Contradictions

**1.1 Where the Unix lineage ends.**
README: "**Text is not data.** This is where the Unix lineage ends: text makes every program re-parse what the last one meant, and OpenLight's **substrate** is typed against itself".
Ontology, Field: "Where Unix had text and the pipe, and the web the page and the link, the medium has the brief and the link." Ontology, Medium: "untyped, because it is prose." Ontology, Code: "Nothing in the code needs new technology: markdown in directories, tracked in git, holds it."
The README ends the lineage at text; the ontology's medium is text and is placed as the lineage's next member. The ontology then ends the lineage one word later (Field: "the medium given addresses and types"), so the line is drawn at a different word. The README also names "the pipe and the file"; the ontology keeps only "text and the pipe".

**1.2 "Interface" changes meaning, twice.**
README, program sense: "carries its interface in its body: what it takes and what it produces". README, UI sense: "**The interface builds on primitives, as data does.** What draws is a **component**". 
Ontology, Interface: "Where comprehension happens: what a knower reads and writes the field through, and what shows the trail." and "The interface the code needs today rests on briefs and links under a gradient and on nothing beneath".
The README's first sense the ontology renames to `contract`; the README's second sense (what draws, components, shell and menus) is not what the ontology's word means. The ontology's interface is a reading-and-writing surface for prose today and a kernel client later; the README's is the built product that "forms around what you are working with".

**1.3 "Harness" changes meaning.**
README: "the field is a first-class harness to everything, every program a tool, every place a context, every run recorded".
Ontology, Harness: "What a tool builds around a model to bound it: a transcript, a closed function, a context made for the occasion. Retired." Ontology, Amplify: "Supersedes the harness ... We do not bound; we expand."
The ontology quotes the README's sentence under "Is dissolved by the field's one fact" but its brief defines the word only as the bound thing that is retired. In the README the word survives with a positive sense (the field *is* the harness); in the ontology it cannot.

**1.4 "The only unit of execution."** *(downstream of declared #2)*
README: "A **program** — the only unit of execution, headless".
Ontology, Program: "The unit of execution in the field, headless" (the "only" is dropped). Ontology, Engine: "A contracted whole of something larger, with its own execution and mechanics" and "Each runs what it runs the way it runs it".
Once engines have "its own execution", the README's "only" no longer holds. The declared divergence does not itself say the README's sentence is false; this does.

**1.5 One rule versus two laws, and which order.**
README: "This entry is written by the one rule we trust most — the why before the how." and, of the specs' defect: "written in the order things are defined rather than the order they are understood."
Ontology, Code: "Has two laws, and everything else follows from them. The first: nothing arrives before its ground; the reader's order is the writer's order." Ontology, Gradient: "every meaning given before it is used, purpose before machinery."
The README's trusted rule is why-before-how and it names definition order as the failure. The ontology's first law, "nothing arrives before its ground ... every meaning given before it is used", *is* definition order, with "purpose before machinery" appended to it as if the same thing. The README treats them as opposed; the ontology treats them as one law.

**1.6 "Ratification" changes meaning.**
README: "the spec tree was rewritten whole from the ratified surface brief (2026-08-22) and is under the author's ratification read".
Ontology, Commit: "Is the ratification, which is this document's rule. Whoever makes a change commits it ... and the other side ratifies by committing on it in turn ... Talk settles nothing; the trail does."
In the README ratification is a read by the author. In the ontology it is a commit, and a read leaves nothing in the medium ("A read leaves nothing in the medium", Trail). Under the ontology's rule the README's "ratification read" ratifies nothing.

**1.7 "Matched, never parsed" becomes "match, never keyword".**
README: "composition is structural — a call is matched, never parsed".
Ontology, Program: "Is bound by the match, never by keyword".
The README's contrast is match against parse (structure against text, the "Text is not data" thread). The ontology's contrast is match against keyword lookup, a different opposite; the parse side of the README's claim is not carried.

**1.8 What the arc builds next.**
README: "code follows the spec, the alignment of the built layer first."
Ontology, Interface: "Is what the arc builds next, since it has to be built to be felt".
The README puts alignment of the built layer first; the ontology puts the interface next.

**1.9 The substrate as law versus circuitry.**
README: "substrate.md (the field's law: chunks, connections, types, boundaries)".
Ontology, Substrate: "the law of laying it down, chunks and their connections, types, boundaries" and then "moves the word below the kernel, beside the processor: circuitry that keeps." Ontology, Processor: "Two kinds of circuitry with no ground beneath: one keeps, one computes."
The position is declared #3. The re-kinding is not: the README's substrate is a law; the ontology's is a law and also the circuitry and the stores ("A store is a directory in the substrate's format"). A law and the disk it is written on are two things, and the README's "Implementation depth ... db.md" is where it keeps the second.

**1.10 Who keeps.** *(downstream of declared #3)*
README: "**The field keeps everything.** Every write is a commit from a bounded process".
Ontology, Kernel: "what the kernel holds is the field open, not the field kept"; Substrate: "Holds the field at rest, as stores ... The commits are kept here; the kernel only serves them." Field: "keeps everything ... Nothing in it is pruned".
The ontology says both that the field keeps everything and that the substrate keeps the commits. The README's third thing is stated of the field; the ontology's keeping happens one word below it.

Noted, not counted: README lists "the three selections" under `view.md`, the experience layer. Ontology, Prism: "The prism, the boundary and a call's argument are all selections of the field, one form read three ways." The README does not define its three, so this cannot be confirmed as a contradiction; but the ontology's three include the boundary, a kernel word, which the README's placement under the experience layer does not suggest.

**Total: 10 contradictions listed; 8 independent of the declared three, 2 downstream consequences of them (1.4, 1.10); 1 further noted and not counted.**

## 3. The three things

The README: "That one fact is the lever, and it moves three things".

**3.1 "Programs compound."**
Carried by: Program ("The unit of execution in the field, headless, carrying its contract in its body"; "Is bound by the match ... attach a peer's store and its programs compound with yours at once"; "a model run as one is still a knower ... Its context a selection of the field, its output landing back as structure"), Contract ("things meet by matching rather than by custom glue"), Citizen ("A citizen's output is ground the next citizen stands on"), Kernel ("Attaches stores on declared terms"), Substrate ("Keeps every contract, which is how anything interoperates"), Harness ("the field is a first-class harness to everything, every program a tool, every place a context, every run recorded").
Whole? **Nearly.** Every sentence of the README's paragraph has a home. Not carried: "the only unit of execution" (see 1.4) and "matched, never parsed" (see 1.7, the parse side is dropped). "a model simply thrives in it" is carried only by Amplify's "We do not bound; we expand."

**3.2 "The interface builds on primitives, as data does."**
Carried by: Contract, "Draws, when it is a component's" ("What draws a screen is a component: a declaration of what it takes, as a program declares what it takes. Which components can draw a thing is a read of the field."); Contract, "Is one value, read three ways" ("a model reads the same contract a person composes with"); Interface, "Is what the arc builds next, since it has to be built to be felt" ("Nobody has had the experience yet.").
Whole? **No.** Carried: the component-as-declaration sentence, "a read of the field", and the last line. Not carried: "Build the small family ... and you soon hold what composes everything else"; "composition is first-class to everyone ... in place"; "the walls between design tool, framework and running product fall"; "The interface is not designed ahead of the data; it forms around what you are working with"; "the whole environment, shell and menus and its own configuration, is field data". The thing is carried by one relation under another word, and the ontology's own `interface` means something else (1.2). This is the thinnest of the three.

**3.3 "The field keeps everything."**
Carried by: Field ("keeps everything ... Nothing in it is pruned"), Commit ("Every change is a commit on a branch"), Boundary ("Is set before a run and stays live during it ... Inspection during, history after: trust is native, because every act is judged under one rule the kernel keeps"), Program ("A run is a process: a boundary before it, inspection during, history after, so every write walks back to the program that made it and the person who ran it"), Trail ("Records a run: what was read, in what order, against which state"), Consolidation ("An inference made from consolidated ground stands on one addressable state, a commit, and can be made again from that state"), Ground ("whatever is stood on holds for whoever stands on it next").
Whole? **Yes, in substance.** "Every write is a commit from a bounded process", "boundaries before a run, inspection during, history after", "Trust is native rather than bolted on", and "the same lossless record is what lets the next reader, person or program or model, stand on exactly what the last one produced" each have a home, some two. The one drift is the word: the keeping is done by Substrate ("The commits are kept here; the kernel only serves them"), not by the field the README names (1.10).

**Total: 3 things; 1 carried whole (3.3), 1 nearly (3.1), 1 not (3.2).**

## 4. Misattributions

**4.1 Substrate "beside the engine".**
Ontology, Substrate: "Ruled by the author, 2026-09-05; the tree still holds it as a tenet beside the engine."
README, reading order: "**The mechanism**, in dependency order — each file uses only what the ones before it define: substrate.md (the field's law: chunks, connections, types, boundaries) → engine.md (running programs against it: ...)".
The README's tree holds the substrate before and under the engine, which runs "against it"; not beside it. "tenet" is not the README's word. This also thins declared #3: the README already has the substrate below what the ontology calls the kernel.

**4.2 The tree's engine as "this word's judge half".**
Ontology, Kernel: "What the spec tree calls the engine is this word's judge half; the rename waits on the arc."
README: "engine.md (running programs against it: stores and attach, the call context, expressions, lifecycle, the protocol)".
The README's engine runs programs. The ontology assigns running programs to a citizen ("The program engine, which runs programs, is one") and gives the kernel only the judging. So the tree's engine is not the kernel's judge half; it is the judge half plus the program engine. The identity is stated as "is".

**4.3 Whose one fact.**
Ontology, Harness: "Is dissolved by the [field]'s one fact. Contracts are chunks in the field they govern".
README: "OpenLight's **substrate** is typed against itself — contracts are chunks in the same field they govern ... That one fact is the lever". Ontology, Substrate, agrees with the README: "The README calls the substrate's one fact, typed against itself, the lever."
The ontology attributes the fact to the field in one brief and to the substrate in another; the README attributes it to the substrate.

**4.4 Compression and handover.**
Ontology, Harness: "A harness as a separate technology no longer exists, and compression and hand-over go with it."
README: "compression and handover happen only by inference over the text itself." and "that dissolves the harness as a separate technology".
The README says the harness dissolves; it does not say compression and handover go. It says they happen badly today. The ontology's own Brief ("Is made by debriefing") and Knower ("a session debriefs before it ends") are handover kept, not gone.

**4.5 The chassis as "a client and a host".** (mild)
Ontology, Kernel: "Beside it, what the tree calls the chassis, a client and a host."
README: "chassis.md (the platform binding and the home)".
The README's description is binding and home; "a client and a host" is the ontology's characterization, offered as if it were the tree's.

**Total: 5 misattributions (4.5 mild).**

## 5. Verdict

It reads as the same project: the lever, the claim, citizen, monolith, trail, boundary, commit-on-branch, "built to be felt" are quoted straight and homed. It drifts in four places. The interface: the README's second thing, its component and environment, has no word, and `interface` means something else. Text: the ontology extends the Unix lineage where the README ends it. Order: the README's one rule, why before how, is folded into a first law that is definition order, the failing the README names. And the tree is mischaracterized twice, substrate beside engine and engine as judge only, weakening two declared divergences.
