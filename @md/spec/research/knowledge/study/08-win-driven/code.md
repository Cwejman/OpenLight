# The code

Comprehension is what most value is built on. Insight compounds when separate understandings join into a larger one. Collaboration rests on that same joining, across people.

That joining comes with friction. We meet it in our own progress, more in a team working toward a common goal, and most in a large organisation. It is felt hardest where we have to join what each of us carries, across different roles.

Every gain in comprehension is a win. The biggest win is the one that gives the most understanding for the least reading.

The code is a set of principles for structuring knowledge into brief wins. The biggest wins come first, and each breaks down into smaller wins, down to every detail that grounds them.

People and models hit the same wall. A person forgets. A model's context fills and gets worse as it fills. Both must hold what matters and reach for the rest. So writing for people and building context for models are one problem, not two.

Folders of markdown are structure too. The difference is that nothing here is typed. No schemas, no edge types, only prose that follows a law. Every part stands on its own. Every connection runs from a bigger win to the smaller wins inside it. That law is what makes the parts compose, and it works now that both readers read language.

What changes is who has to explain. Nobody is walked through anything, and the person who knows a thing stops being the only way to it. A new colleague, or a fresh session, opens the top and reads down to the depth their task needs. The same decision is not made twice, because it has one home. And the knowledge gets better as it grows, not worse. Each addition lands where it belongs, and the top stays short.

For a model the change is sharper. A session can let go of what it no longer needs, because the part above holds the point, and no harness today can do that. Programs written to this code keep the structure connected and current. What is left to people is what machines do not hold.

A program that did this well would have to hold everyone in, and everyone's knowledge with them. The AI tools built so far do not. They are monolithic, like most knowledge systems and the tools we use with them. But nothing new has to be built to put the code to work. It pays soonest in IT, where part of the group already works with agent harnesses. A [proof of concept]() runs this thesis on folders of documents, with the tools that exist.
