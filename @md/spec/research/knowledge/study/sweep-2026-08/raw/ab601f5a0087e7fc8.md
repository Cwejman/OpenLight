## 1. Academic / empirical work

**The strongest negative result.** "Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?" — Gloaguen, Mündler, Müller, Raychev, Vechev (ETH Zürich / LogicStar), arXiv:2602.11988, submitted 12 Feb 2026, revised 23 Jun 2026 (https://arxiv.org/abs/2602.11988). Two datasets: SWE-bench tasks with LLM-generated context files per agent-vendor guidance, plus a fresh set of issues from repos with *developer-committed* context files. Finding: context files "do not generally improve task success rates, while increasing inference cost by over 20% on average," across multiple models and agents. Agents *did* follow the instructions — repository overviews, the most-recommended content type, simply didn't help. **paper-only, but high-credibility group.** This is the single most important citation for the question and it points the opposite way from vendor guidance.

Corroborating, weaker: "Do Context Files Help Coding Agents? A Two-Agent Ablation Study on Real Repositories," Prakhar Khatri (single author, independent), arXiv:2607.27250, 28 Jul 2026 — Claude Code + Codex, 17 tasks / 3 repos / 288 runs, gold-test eval; equivalence testing bounds any effect at ≤10–15pp; failures attributed to implementation skill, not missing repo knowledge. **paper-only, low power** (n=17 tasks cannot detect small effects — "no measurable difference" here is not "no effect").

**The strongest positive result is about tool descriptions, not prose docs.** "MCP Tool Descriptions Are Smelly!" — Hasan, Li, Rajbahadur, Adams, Hassan (Queen's University / Huawei), arXiv:2602.14878, 16 Feb 2026, rev. 31 May 2026 (https://arxiv.org/abs/2602.14878). 856 tools / 103 servers; 97.1% carry ≥1 "smell," 56% don't state purpose. Augmenting descriptions: **+5.85pp median task success, +15.12% partial goal completion — but +67.46% execution steps and regressions in 16.67% of cases.** Causal (intervention), but modest and not free. **paper-only.**

"From Docs to Descriptions: Smell-Aware Evaluation of MCP Server Descriptions" — Wang, Li, Sun, Liu, Liu, Tian, arXiv:2602.18914, 21 Feb 2026. 10,831 servers surveyed, 18 defect classes; then a **mutation-based controlled experiment**: standard-compliant descriptions reach 72% selection probability vs a 20% baseline. The widely-quoted "**260% more often**" (e.g. https://glama.ai/blog/2026-04-03-tool-description-quality-score-tdqs, 3 Apr 2026) is that 20%→72% restated as relative lift — real and experimental, but it measures *tool selection among competitors*, not task success. Treat the bare "260%" as **near-FOLKLORE framing of a real number**.

Older baseline worth citing: ToolTalk (arXiv:2311.10775) ablated tool/parameter descriptions to names+types only and saw across-the-board degradation — the crude version of the effect.

Context-quality benchmarks now exist: ContextBench (arXiv:2602.05892) — measures context recall/precision/efficiency in coding agents, finds scaffolding yields only marginal retrieval gains; SWE Context Bench (arXiv:2602.08316, 1,100+376 tasks); LOCA-bench (arXiv:2602.07962). **paper-only.** I found no ICSE/FSE/MSR/SIGDOC 2026 accepted paper specifically on human-doc quality → agent success; the ICSE 2026 AGENT workshop (Rio, 12–18 Apr 2026) is the venue where such work would land.

## 2. Conventions

**llms.txt: shipped-niche, and the SEO claims are dead.** SE Ranking, 300k domains, published 7 Nov 2025 (https://seranking.com/blog/llms-txt/): 10.13% adoption, evenly spread across traffic tiers, and **no correlation with AI citation — dropping the llms.txt variable *improved* their XGBoost model**. Gary Illyes (Search Central Live, July 2025): Google does not support it and has no plans to; John Mueller compared it to the keywords meta tag (https://www.searchenginejournal.com/google-says-llms-txt-comparable-to-keywords-meta-tag/544804/). **No LLM provider has confirmed consuming it.** Where it does work is agent tooling that fetches it on demand — Claude Code, Cursor, Copilot, Aider.

**AGENTS.md: shipped-and-widely-adopted, effectiveness unproven.** agents.md states "used by over 60k open-source projects" and stewardship by the Agentic AI Foundation (Linux Foundation); OpenAI's AAIF announcement is at https://openai.com/index/agentic-ai-foundation/. Note the tension: widest adoption, and the only rigorous evaluation (2602.11988) says it doesn't move success rates.

**Agent Skills / SKILL.md: shipped, fast-growing.** Anthropic published the spec as an open standard in Dec 2025 (agentskills.io; https://thenewstack.io/agent-skills-anthropics-next-bid-to-define-ai-standards/), since adopted by Codex CLI, Cursor, Copilot, Microsoft Agent Framework. Eval work already exists — SkillTester (arXiv:2603.28815), SkillAxe (2606.10546), SkillResolve-Bench (2606.10388) — plus a Snyk audit (Feb 2026) of 3,984 public skills: 534 with a critical security issue.

## 3. Vendor data

Mintlify midyear report, 29 Jul 2026 (https://www.mintlify.com/blog/state-of-docs-traffic): agents = **66% of docs traffic** (213M agent requests vs 105M human page loads in July), up from 15.2% in January; direct Markdown requests 25.1%→54.4% Feb→Jul; 1.42M MCP tool calls in July. Their March 2026 report (https://www.mintlify.com/blog/state-of-ai) covers ~790M requests over 30 days, classified by Cloudflare user-agent — and concedes Codex sends no identifiable UA, so the figure is a floor. GitBook reports agents going from <10% of doc reads (Jan 2025) to the majority of "intentional reads" by May 2026. Mintlify also claims a 20-site benchmark where serving llms.txt "reduced error rate by almost 90%" (agent URL mistakes) — **vendor claim, methodology undisclosed, and it measures navigation errors, not task success.** Grade: opinion/marketing-adjacent until methods are published.

## Bottom line

The causal evidence splits cleanly: **machine-facing descriptions (tool/API schemas) demonstrably matter** (+5.85pp success, 20%→72% selection, both experimental); **human-prose repo context files demonstrably do not, at measurable cost** (+20% inference spend, no success gain). Traffic data proving agents *read* docs is abundant and vendor-sourced; evidence that better docs make agents *succeed* is thin, recent, and mostly about schemas.
