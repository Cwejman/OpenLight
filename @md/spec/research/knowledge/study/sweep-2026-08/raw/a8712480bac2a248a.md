# Findings

## 1. RDF 1.2 — NOT a Recommendation (as of 2026-08-26)

Authoritative source: the W3C RDF & SPARQL WG publications page, fetched 2026-08-26 — https://www.w3.org/groups/wg/rdf-star/publications/

- **Candidate Recommendation Snapshot, 7 April 2026**: *RDF 1.2 Concepts and Abstract Data Model*, *RDF 1.2 Semantics*. Concepts' status section: "This Candidate Recommendation is not expected to advance to Recommendation any earlier than 05 May 2026" (https://www.w3.org/TR/rdf12-concepts/). That date has passed with no PR transition — the two CRs are still the most advanced documents in the suite, 4½ months later. W3C news item inviting implementations: https://www.w3.org/news/2026/w3c-invites-implementations-of-rdf-1-2-concepts-and-abstract-data-model-and-rdf-1-2-semantics/
- **Everything else is still Working Draft**: Turtle 1.2 (12 Aug 2026), N-Triples 1.2 and N-Quads 1.2 (23 Jul 2026), TriG (12 Jun 2026), RDF/XML 1.2 (18 Jun 2026), RDF 1.2 Schema (28 Mar 2026). Concepts cannot exit CR until "at least one specification for a concrete syntax" exits CR — so **no concrete syntax has even entered CR**, and RDF 1.2 is structurally blocked.
- **Schedule slip**: the charter (https://www.w3.org/2025/04/rdf-star-wg-charter.html, group renamed from "RDF-star" to "RDF & SPARQL") targeted RDF 1.2 Rec in **Q3 2025** and SPARQL 1.2 Rec in **Q4 2025**. Charter runs to 30 April 2027. Actual: ~1 year behind, and the *What's New in RDF 1.2* note (Group Note Draft, 14 July 2026, https://www.w3.org/TR/rdf12-new/) still has an **empty §2 "Abstract Syntax"** and §3–§4 describing RDF *1.1* changes. Grade: **announced**, not shipped.

**The design shift.** RDF-star (CG report) had *quoted triples* usable in subject **or** object position, treated as referentially **opaque**. RDF 1.2 Concepts §3.1 (fetched 2026-08-26) defines triples inductively such that a triple term may appear **only as the object**. §1.5 introduces `rdf:reifies`: a *reifying triple* whose subject is a *reifier*; triple terms are declared **transparent** ("`:Alice` from a triple term and `:Alice` in an asserted triple both denote the same resource"). The stated rationale: "There can be multiple, distinct reifiers related to the same abstract proposition, such as statements with different sources" — i.e. the CG's quoted triple was a *type*, not a *token*, so you could not attach two conflicting provenances to the same statement. Opacity was also incompatible with entailment. Two conformance profiles now exist: **RDF 1.2 Full** and **RDF 1.2 Basic** (no triple terms) — a hedge that lets implementers skip the feature entirely.

## 2. SPARQL 1.2 — all twelve documents are Working Drafts

*SPARQL 1.2 Query Language*, W3C **Working Draft, 20 August 2026** (https://www.w3.org/TR/sparql12-query/). New vs 1.1: triple-term support with `TRIPLE`, `SUBJECT`, `PREDICATE`, `OBJECT`, `isTRIPLE`; a **`VERSION` directive** with labels `"1.2"`, `"1.2-basic"`, `"1.1"`; language-direction functions; hash-function updates. Protocol (23 Jul 2026), Update (12 Jun 2026), Federated Query and Service Description (23 Apr 2026), Entailment Regimes (9 Apr 2026) — all WD. Query Results XML Format and Graph Store Protocol have not been touched since **December 2024**. "SPARQL-star" as a name is gone; it is just SPARQL 1.2. Grade: **announced**.

## 3. SHACL 1.2 — Rec-track, but no CR anywhere

SHACL 1.0 Rec: 20 July 2017. Data Shapes WG chartered **until 31 December 2026**; chairs Nicholas Car and Eliana Papoutsoglou (https://www.w3.org/groups/wg/data-shapes/). Publications page fetched 2026-08-26 (https://www.w3.org/groups/wg/data-shapes/publications/):

- **SHACL 1.2 Core** — WD, 3 Aug 2026 (https://www.w3.org/TR/shacl12-core/). New: node expressions, `sh:targetWhere`, `sh:ShapeClass`, reification-based messages/severity.
- **SHACL 1.2 SPARQL Extensions** — WD, 21 Aug 2026
- **SHACL 1.2 Node Expressions** — WD, 21 Jul 2026
- **SHACL 1.2 Rules** — WD; **SHACL 1.2 UI** — FPWD 26 May 2026; **SHACL 1.2 Profiling** — FPWD 2 Jul 2026
- **SPARQL 1.2 RL** — WD, **25 Aug 2026** (https://www.w3.org/TR/sparql12-rl/): "a datalog-style rules language for RDF… inferencing with the generation of new RDF data."

Two observations. First, the 2017 *SHACL Advanced Features* and *SHACL JavaScript Extensions* Notes are being promoted to Rec track. Second — important for Q6 — **the shapes WG, not an OWL WG, is now standardising the mainstream RDF inference language**, and it is datalog, not description logic. No Rec-track dates published; charter expires in ~4 months, so a re-charter is near-certain.

## 4. ShEx — alive as a community, dead as a shipping standard

- Last formal spec: **ShEx 2.1, Final Community Group Report, 9 August 2019** (https://shex.io/shex-semantics/). Never a W3C Recommendation; never had a W3C WG.
- npm `shex`: latest release **1.0.0-alpha.29, 2023-11-11**; **379 downloads** 2026-07-26→2026-08-24 (registry.npmjs.org + api.npmjs.org, fetched 2026-08-26). Compare `rdf-validate-shacl`: **123,083/month**. That is a ~325× gap.
- Repos are alive but unreleased: shexjs/shex.js 62 stars, pushed 2026-08-23; shexSpec/spec 17 stars, pushed 2026-08-20; weso/shex-s 6 stars, last pushed 2025-04-25 (GitHub API, 2026-08-26). Labra Gayo's successor project **rudof** (Rust, ShEx+SHACL): 117 stars, pushed 2026-08-24.
- **Wikidata EntitySchemas are genuinely alive**: MediaWiki API count of namespace 640 = **461 EntitySchema pages**; recentchanges shows edits on 2026-08-20/21/22/23/24 by multiple users including `Jelabra` (Labra Gayo) editing E371 on 2026-08-24. Grade: **shipped-niche**.
- **Folklore warning**: PyPI `pyshex` shows 315,273 downloads/month, which looks like healthy ShEx adoption. It is not — the repo is `linkml/PyShEx` and it rides on LinkML (343,225/month). Treat that number as transitive, not as ShEx users.

## 6. The shapes-vs-OWL argument

The canonical text is Holger Knublauch, *SHACL and OWL Compared* (https://spinrdf.org/shacl-and-owl.html, last updated **17 August 2017**): OWL's open-world semantics mean a missing required property yields no error; without a unique-name assumption, `owl:maxCardinality 1` with two values makes a reasoner *infer* the two IRIs are co-referent; "OWL does not constrain anything but rather describes inferences," so a reasoner "add[s] to the data in attempt to conform." **Flag: Knublauch is TopQuadrant's CTO and TopQuadrant sells SHACL tooling — this is the argument's clearest statement, but it is an interested party's opinion, not an assessment.** It is nonetheless the source most SHACL advocacy silently reproduces.

Supporting, non-vendor evidence: Warren, Mulholland, Collins & Motta, *Improving comprehension of knowledge representation languages: A case study with Description Logics*, IJHCS 2019, doi:10.1016/j.ijhcs.2018.08.009 — empirical evidence that practitioners systematically mis-reason about DL/OWL semantics. Grade: **paper-only**, and it measures comprehension, not deployment.

Convergence rather than victory is the current research posture: arXiv 2608.14104, *Rewrite Once, Validate Anywhere: Producing OWL-Aware SHACL Constraints* (14 Aug 2026); doi:10.14778/3681954.3682023, *Efficient Validation of SHACL Shapes with Reasoning* (PVLDB 2024); doi:10.1007/978-3-030-95481-9_6, *A Review of SHACL: From Data Validation to Schema Reasoning* (2022). And, as noted, the W3C is reintroducing inference as **SPARQL-RL datalog** under the shapes group — the practical answer to "validation vs reasoning" is turning out to be *rules*, not description logic.
