## Local-First & Sync Engines — State of the Field, August 2026

**Headline:** the field consolidated hard in 12 months. Three of the best-known independent players exited (Electric→Databricks, Triplit→Supabase, InstantDB→OpenAI). Meanwhile the *substrate* (Yjs, PGlite) exploded in downloads, largely pulled by AI tooling rather than by collaborative-app demand.

### CRDT libraries

**Yjs — shipped-and-adopted (dominant, uncontested).** ~31.6M npm downloads/month; the 1–20 Aug window shows 20.95M vs 3.78M in 2025, 1.64M in 2024 — ~5.5× YoY (api.npmjs.org, fetched 2026-08-26). Stable line is v13.6.32 (2026-08-04); **v14 has been stuck in RC — v14.0.0-rc.24, 2026-07-15** (github.com/yjs/yjs/releases). v14's theme is versioning/track-changes, presented at FOSDEM 2026 by the BlockNote+Yjs teams, *funded by ZenDiS (OpenDesk) and DINUM (La Suite Docs)* — i.e. European public-sector money, not VC (fosdem.org/2026/schedule/event/8VKQXR). Kevin Jahns remains sole maintainer; funding runs through Y-Collective on Open Collective, which caps maintainer billing at $100/h "as long as there is funding" (opencollective.com/y-collective). **Yrs/y-crdt is healthy**: v0.27.4, 2026-08-22. Tiptap ~18M/mo, Hocuspocus active (pushed 2026-08-22). Liveblocks (~390k/wk) still lists Yjs but its 2026 blog is almost entirely AI copilots/agents (liveblocks.io/blog). **Y-Sweet (Jamsocket) — shipped-niche, near-idle:** last commit 2025-12-04, ~9k/wk.

**Automerge — shipped-niche, technically strong.** Automerge 3.0 (July 2025) cut memory >10×: Moby-Dick-sized doc 700MB→1.3MB; one doc load went 17 hours→9 seconds (automerge.org/blog/automerge-3/). Text API removed, columnar format now used in-memory. Automerge-repo 2.0 (May 2025); 3.x ships by default from repo 2.1.0. Latest js/automerge-3.4.1 (2026-08-12). Still ~126k downloads/20 days — **~250× smaller than Yjs**. Active work (automerge.org/blog/2026-july/): **Hexane v1** storage engine (2–9× faster), **Subduction** sync server hardening (redb backend, per-peer rate limiting), **Keyhive** E2EE + the **BeeKEM** paper (preprint July 2026), and commit-level author provenance. Named users are all small/lab-adjacent: Allume (ex-Muse), Backstitch (Godot plugin, shown at GodotCon 2026), Braid, Coln, Teamtype. No large-scale production logos disclosed.

**Loro — shipped-niche, rising.** loro-crdt 1.14.1 (2026-08-10), ~161k/wk. A June 2026 data-loss issue in concurrent editing was reported and addressed (localfirstnews.com, 2026-06).

### Sync engines

**ElectricSQL — shipped-and-adopted, then acquired.** The 2024 pivot (drop client CRDTs, read-path-only "shapes" over Postgres) worked commercially. Electric 1.0 shipped March 2025; 1.1 added a storage engine with "100× faster writes"; 2026 additions include Durable Streams, StreamDB, and Electric Circuits (July 2026). **Databricks acquired Electric, announced 2026-08-11/12** (techtarget.com/data-technologies/news/366649200; electric.ax/blog) — joining Neon under Lakebase, "everything we've open sourced stays open source." Domain moved electric-sql.com → electric.ax. **PGlite is the real prize: ~15M npm downloads/week** (verified 2026-08-26), 15.9k stars — WASM Postgres for agent sandboxes, not for collaborative apps. @electric-sql/client 4.2M/mo. Repo active (pushed 2026-08-21).

**Zero (Rocicorp) — shipped, GA, adoption unproven.** Zero 1.0 announced 2026-06-08 (infoq.com/news/2026/06/zero-version-1/); Rocicorp's own status page dates GA to **March 2026** — the two don't agree, treat 1.0 as symbolic (0.26.2 → 1.0 with minimal functional change). Model per zero.rocicorp.dev/llms.txt: `zero-cache` holds a SQLite replica of Postgres via logical replication; clients **cannot send arbitrary ZQL** — you register named queries/mutators (`defineQueries`/`defineMutators`), the server resolves name+args to ZQL and enforces permissions, client runs the same ZQL optimistically against IndexedDB. npm 442k/mo; rocicorp/mono pushed 2026-08-26. Documented gaps: Postgres-only, no SSR, no aggregates/group-by, no column permissions, no JSON filtering, no first-class text search, 232KB gz client. Cloud Zero is commercial, "full public availability during 2026." **No funding announcement found.**

**Jazz — announced (v2 alpha), unfunded.** Jazz v2 public alpha 2026-04-18 — a near-total rewrite that walks back the original thesis: crypto-enforced permissions → **server-as-authority**; CRDTs → **git-like snapshot DAGs**; bespoke JSON-graph API → relational model with ORM queries (jazz.tools/blog/what-we-learned-from-classic-jazz). Tracxn lists Jazz as **unfunded**, founded 2022, Canterbury UK. jazz-tools ~11k/mo — tiny. But repo is one of the most active in the field (100+ commits/12mo, last 2026-08-26) and Jazz sponsored Local-First Conf 2026.

**Triplit — dead as a product.** Acquired by Supabase, announced **2025-10-08** (supabase.com/blog/triplit-joins-supabase). Supabase explicitly did *not* integrate it: Matt Linkous works on third-party sync integrations (Electric, Zero, PowerSync) instead. Repo: **3 commits in the last 12 months, last commit 2025-09-11**. Supabase's own line: "solving offline mode in a way that works for everyone is a formidable challenge."

**InstantDB — dying (dated shutdown).** instantdb.com now carries: **"Instant is sunsetting. Services will continue until August 31st, 2027"** — the team joined OpenAI (essay `instant_team_joins_openai`). Verified 2026-08-26. YC-backed; investors included Greg Brockman, Jeff Dean, Paul Graham. Repo still pushed 2026-08-25 but this is a wind-down, not a roadmap.

**PowerSync — shipped-and-adopted.** Monthly releases (@powersync/web 2.2.0, 2026-08-13); connectors for Postgres, MongoDB, MySQL, SQL Server; HIPAA; **migration guides published *from* Electric Cloud and Atlas Device Sync** — it is absorbing refugees. 264k/mo.

**Ditto — shipped-and-adopted (the quiet commercial winner).** SDK 5.1 (Aug 2026): 189 improvements, joins, mesh-wide certificate revocation, multicast sync beta. Real edge deployments — aviation, defense (ATAK), retail POS (ditto.com/blog).

**Convex — not local-first, but the best-funded neighbour.** **$57M Series B led by Insight Partners, August 2026**; ~10,000 paying teams; EU hosting Feb 2026 (news.convex.dev). 5.35M npm/mo. Server-authoritative reactive DB — adjacent, not local-first.

**Others (verified 2026-08-26):** **RxDB** live (23.4k stars, daily commits, 307k/mo, commercial premium). **Dexie** 9.1M/mo; Dexie Cloud in production, per-seat from €3/mo. **TinyBase** active (5.2k stars, pushed 2026-08-19, 71k/mo). **Evolu** active (pushed 2026-08-25), post-quantum E2EE sync — shipped-niche. **LiveStore** (Schickling) still pre-1.0: v0.4.0 2026-06-02, v0.5.0-dev.0 2026-08-24, 60k/mo — shipped-niche, event-sourcing model. **SQLSync — stalled**: 7 commits/12mo, last 2025-11-19. **cr-sqlite — stalled**: last release v0.16.3 **January 2024**, 5 commits/12mo. **Turso** pivoted away: 24k stars, extremely active, but now "building Postgres in Rust… the LLVM of databases" and DB-per-agent; libSQL offline sync is no longer the story. **TanStack DB** is the new integration layer — adapters for Electric, PowerSync, RxDB, TrailBase.

## Schema evolution — the deep dive

**Cambria is research-prototype, and its code is dead.** Litt & van Hardenberg, *"Cambria: Schema Evolution in Distributed Systems with Edit Lenses"* (PaPoC'21, doi 10.1145/3447865.3457963); inkandswitch.com/cambria. Bidirectional YAML/JSON lenses, one lens generating both directions, plus `cambria-automerge` for p2p. **github.com/inkandswitch/cambria-project: last push 2024-06-14, 698 stars, never productionized.**

**Jazz v2 is the only shipped Cambria descendant.** "Fluid migrations" (jazz.tools/blog/four-fresh-ideas-behind-jazz, 2026-04-18) states the problem exactly — *old clients writing against outdated schemas that sync later into newer server schemas* — and solves it with two moves: (1) **schema version as an extra branch dimension** on Jazz's native per-row branching, so "a row with a stable identity can then coexist in different schema branches at once"; (2) explicitly citing Cambria, migrations as **"purely functional mappings between schema versions,"** bidirectional so "old data [is] readable in the new format *and* new data readable in the old." Goal: no stop-the-world freeze, and "whole graphs of mutually compatible schema versions." Grade: **announced/alpha** — the idea is now in a shipping product's design, not yet in production at scale.

**Everyone else solves it by forcing clients to upgrade.**
- **Zero**: pure deployment discipline. Expand = DB→API→Client; contract = Client→API→DB; wrong order "will cause downtime." Client sends its build-time schema on connect; incompatibility triggers `onUpdateNeeded`, which **reloads the page by default** (zero.rocicorp.dev/docs/schema). No data translation whatsoever.
- **Electric**: Postgres is source of truth, so upstream PG migrations govern; a shape's schema change forces client resync. The problem is punted to the server — which is precisely what the 2024 pivot bought.
- **Automerge**: no built-in migration story. Docs are schemaless JSON-like; convention is defensive reads plus app-level init/migrate. The Cambria integration was never carried into Automerge 2/3.
- **Yjs**: no schema at all — shared types are untyped; migration lives in the ProseMirror/BlockNote schema layer. **v14's investment is versioning and track-changes, not schema evolution.**
- **InstantDB**: declarative TS schema with undo for destructive changes (moot given the sunset).

**Still framed as open.** LFC 2026 Day 2 closed with Seph Gentle's **"Stable Schemas, Mutable Software"** — five years after Cambria, the framing is still *decouple stable data schemas from mutable app code*, and no one is claiming it solved.

**Branching/versioning is healthier than migration.** Automerge has first-class branches/history; **Ink & Switch's Patchwork** is the live research vehicle (100+ commits/12mo, notebook entries through 2026-05-12, "Version Control" book 2024, inkandswitch.com/patchwork/notebook/) and hosts LFC Lab Day. Shipping instances: **Backstitch** (Automerge branch/merge for Godot scenes, GodotCon 2026), Jazz v2's per-row git-like history, Yjs v14 track-changes. **Zero and Electric have no branching story at all** — the SQL-replica engines bought adoption by giving up exactly the capability the CRDT camp is still building.
