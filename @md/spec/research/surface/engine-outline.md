## The load-bearing deltas (what makes this a rewrite, not an edit)

1. **The engine becomes its own installed artefact.** Kills the header's "Rust crate compiled into the host binary" and every host-direct assumption downstream: the `HostCmd` channel (`MountWebview`/`EvaluateScript`), the wry-IPC transport, "callable from the host" framing. Every client — chassis included — speaks the one protocol over a transport the environment installs. The Rust API section survives only as the crate's internal shape, no longer the host contract.
2. **Mounts → attach.** "One read-write active project plus read-only mounts," boot-time mounting, `engine/mount`, read-only enforcement, "federation in Rust, not SQL" — all superseded by the attach era: stores by recognition, the one attach record shape, `attach`/`detach` as engine-owned native programs (walled by `run`, so run-to-draft governs them), write declared at attach and routed to the owning store, **one connection, all stores, one evaluator** [P], commits per-store, cross-store acts as per-store sequences with every prefix safe, `[engine/attached]` virtual. The word *mount* leaves the engine's store vocabulary entirely — view owns it now.
3. **Programs are headless.** `runtime: vm | native`; `webview` retires and the surface runtime dies with the seat mechanism. Cascades: the surface rows in the terminal-signal table, `exit` as surface self-dismissal, the one-compositor section, the same-DOM/iframe containment tiers, per-slot identity tokens — the visual halves move to the view specs (as pointers here), the engine keeps VM + native + the guarantee that boundary checks compose with any containment.
4. **The call context becomes the center of the boundary story.** New section: the engine's own structural contract — declaration + argument + grant + derivable parent; effective reach intersecting up the chain to the machine context (`Context::process_id = None`, re-meant from "host-initiated" to the root of the chain); `Context` gains `{ anchor }` [P]; batch reads carry the anchor per entry; the chain derived from field data, cacheable. A process is the *near*-conformer: the frame is a fifth source, cap-exempt — its seat in the generic contract is the named open. Intents dissolved; the engine judges ordinary commits and starts under the anchor's reach.
5. **The ceiling changes from cap to source.** Old law: ceiling present = exact bound the run may narrow, absent = defers to the run. New law [R, cross-cutting]: reach = frame ∪ argument ∪ ceiling ∪ starter additions, ∩ parent; **an absent ceiling key means `{}`**; the parent's reach enters only where the ceiling names **`caller`** (composable: `caller − [secrets]`). Never-widen stands. This rewrites *Boundaries* source 3 and touches every sentence that says "defers."
6. **Capabilities are `net` · `fs` · `exec`, nothing else**, with modes, composing by intersection; the keychain and `secret:<NAME>` retire (secrets are a module; `read-secret` declares `exec`). Enforced by the runtime at spawn — and honestly staged: before the VM lands, declared, recorded, shown at Go, **not enforced**.
7. **The engine serves sources.** `ol://` resolves through the engine — new section; constraint: a module's files live under the store's version control, so pinning a commit pins chunks and code together.
8. **`launch`'s owner is configured.** The session is desktop-module state, not an engine concept — *Two modes* reworked; starts from mounts are `launch`, capped by the mount's reach, no frame.
9. **Daemons ruled.** Impure programs launchable like any; purity never the launch gate (it only decides what the planner may evaluate); nothing auto-starts; absent service → the component's fault face (view). The resident-lifecycle open (terminal-as-policy) stays open; gestureless starts deferred.
10. **Offers bind by the match.** New clause in *The match*: unbound optional `accepts` entries bind from the caller's standing offer; explicit binding wins; ambiguity binds nothing and says so.

- **C2 — the collation shape.** engine.md holds `collation { selections: list<selection>, … }`; the brief's view section holds `collation { mounts: list<ref(view/mount)>, … }`. Members become mounts (calls), not bare selections. I move collation's definition out of engine.md to the view family and leave expressions/`engine/expression` here. Confirm the move.
- **C3 — instance removal.** The cross-cutting ruling says "instance removal requires write over the placed chunk," which contradicts the current placement law (remove = write over the dimension). I fold it as stated for `instance` placements only — the claim-your-type symmetry — leaving `owned`/`relates` removal with the dimension. Confirm this reading; it also lands in substrate.md.
- **C4 — `exit`.** Surface self-dismissal dies with surface programs. A VM program exits by exiting. I retire the op. Confirm.
