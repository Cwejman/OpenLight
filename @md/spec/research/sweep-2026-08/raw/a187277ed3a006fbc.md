## 1. HEADLINE

- **Letta/MemGPT — the flagship of the "memory OS" thesis — retired its own server.** The Python Letta V1 server is preserved on an `archive` branch and `letta-ai/letta` is now "a landing page"; development moved to `letta-ai/letta-code`, a TypeScript **coding-agent harness** on npm. Commit activity in the old repo: **12 commits Apr–Aug 2026 vs 1,115 in the preceding 21 weeks.** ([README](https://github.com/letta-ai/letta), commit `chore: archive the legacy server repository` 2026-08-16)
- **Anthropic shipped the whole layer as product, starting the same month the April survey ran.** Claude Managed Agents public beta **2026-04-08**; agent **memory stores** public beta **2026-04-23**; **Dreams** (background memory consolidation) research preview **2026-05-06**; memory got its own API version `agent-memory-2026-07-22` on **2026-07-02**. ([release notes](https://platform.claude.com/docs/en/release-notes/api))
- **Every serious memory vendor now converges on the same three features, and two of them ship them after Anthropic did**: background consolidation ("dreaming" — Anthropic 2026-05-06, Mem0 "Dream" 2026-08-04, Letta `/sleeptime`), cross-harness memory ("your Claude Code and your Cursor don't share what they know" — Zep 2026-08-19, Mem0 "Beyond AGENTS.md" 2026-07-29, Letta `trajectory` 2026-07-10), and provenance/versioning.
- **OpenAI deprecated Agent Builder, the Evals platform and reusable prompt objects on 2026-06-03** (shutdown 2026-11-30), pushing users to the code-first Agents SDK or "ChatGPT Workspace Agents". The visual agent-composition layer died; the SDK layer grew (891 commits vs 458). ([deprecations](https://platform.openai.com/docs/deprecations))
- **The benchmark layer collapsed as evidence.** Three 2026 papers show LoCoMo/LongMemEval leaderboards are uninterpretable: retrieval-budget confounds (Graphiti "wins convincingly but uses 2.6M characters of retrieved context per query… after controlling for retrieval budget the lead disappears", [2607.16848](https://arxiv.org/abs/2607.16848), 2026-07-18); recall-without-precision ([2605.11325](https://arxiv.org/abs/2605.11325)); and serving cost never measured ([2608.11879](https://arxiv.org/abs/2608.11879), 2026-08-12). Meanwhile HN is full of "beats Mem0 on LoCoMo" launches — the benchmark is now a marketing token.
- **Memory poisoning is the unsolved hole.** 1.2% poisoning of a LongMemEval corpus drops accuracy **0.850 → 0.300**; a write-time screening pipeline "rejects 0 of 360 poisoned memories"; shipped provenance-weighted retrieval is "statistically indistinguishable from no defense (p=0.80)" ([2608.21230](https://arxiv.org/abs/2608.21230), 2026-08-21).
- **Daytona's open source is dead.** "As of June 2026, Daytona's core development has moved to a private codebase. This repository will receive no further updates" — 71.9k stars, last commit 2026-06-25. E2B kept shipping (releases through 2026-08-25).

## 4. THE COMMODITISATION QUESTION

**Yes, from above — and faster than the April survey could have seen.**

The decisive evidence is not marketing but API surface with version headers. Anthropic's memory store is a *workspace-scoped collection of text documents*, mounted into the sandbox at `/mnt/memory/<slug>/`, where "each memory in a store is addressed by a path", "**every change to a memory creates an immutable memory version**", versions "belong to the store (not the individual memory) and survive even after the memory itself is deleted", `access: read_only|read_write` is "enforced at the filesystem level", and writes "produce memory versions **attributed to the session**". There is a `redact` endpoint that "scrubs content out of a historical version while preserving the audit trail". Limits: 100 kB per memory, 2,000 memories per store, 8 stores per session, 30-day version retention. Google's Memory Bank independently shipped **memory revisions** plus **IAM-Conditions access control**. Both labs now sell scope isolation, versioned facts and audit — three of the six cross-cutting conclusions the April survey drew.

**But the absorption is partial and shaped, which is where the remaining room is:**

1. **The labs bet on files, not graphs.** Anthropic's memory is markdown documents at paths; Google's is generated memories with profiles. Neither has bi-temporal edges, invalidation-not-deletion, or fact-level provenance. Zep's answer is literally titled "Markdown is not agent memory" (2026-06-23), and its provenance model — edges carry "an `episodes` list holding every episode that contributed to its fact", with `valid_at`/`invalid_at` accumulating rather than overwriting, so deletion scope is computable — is genuinely more expressive than a file version list.
2. **The labs' memory is per-vendor.** The one thing no lab will build is *memory across harnesses*, which is exactly the gap Zep (2026-08-19), Mem0 (2026-07-29) and Letta's `trajectory` (2026-07-10) all rushed into within six weeks of each other. That convergence is the market telling you where the non-commoditised niche is.
3. **The tooling tier is being squeezed harder than the memory tier.** OpenAI killing Agent Builder and its own Evals platform, LlamaIndex's commercial pivot to "Parse" (agentic OCR/extraction) while its OSS commits halved (198 vs 449), and Daytona closing its source, all say the same thing: undifferentiated middleware between the model and the user has ~18 months.

**Implication for anyone building here:** do not build a memory store. Build the thing the labs structurally cannot: cross-vendor, or fact-level-temporal, or provenance-over-the-changed-data. And assume file-plus-version is the free floor you must beat.

## 5. THE FOUR CAPABILITY TESTS

**(a) Branch an agent's context and resume from an arbitrary point — PARTIAL, at the harness tier only.**
LangGraph is the strongest shipping answer: checkpointers persist "a thread's graph state as checkpoints… for conversation continuity, human-in-the-loop workflows, **time travel**, and fault tolerance", with `checkpoint`/`checkpointpostgres`/`checkpointsqlite` released through 2026-08-07. Claude Code (`/branch`, `--fork-session`, `/rewind`), Codex CLI (`/fork`, `/side`) and Letta Code (forked subagents) do it in the CLI. **Anthropic's Managed Agents session API does not** — I read the sessions doc end to end: you get pinning, per-session overrides, interrupt/redirect, `initial_events`, budgets; there is no fork, rewind, checkpoint or replay endpoint. And [2608.22928](https://arxiv.org/abs/2608.22928) (2026-08-24) states the obvious problem nobody has solved: existing systems fork without deriving what the edit must preserve, so "an unsafe edit can… authorize the same tool action twice, discard a result the task still requires, or conflict with a call that began before the edit." **Nobody has safe branching in production.**

**(b) Reproduce a completion exactly from a recorded, addressable context — NO.**
Closest: Letta's `trajectory` normalises transcripts from multiple harnesses into "deterministic, structured records"; Anthropic's Console session viewer exposes raw events grouped by model request; Eywa reports results "under a frozen, artifact-recorded retrieval configuration". But nothing addresses the *exact request payload* as a first-class, re-submittable, content-addressed object across a version boundary, and server-side compaction (Anthropic, 2026-02-05) and Dreams actively make the recorded context non-reconstructible from the transcript. Reproducibility is being traded away for context economy, deliberately.

**(c) Enforce per-run permission boundaries over what an agent may read and write, uniformly — CLOSEST TO SOLVED, per-platform.**
Anthropic now has: per-session memory-store `access` enforced at the filesystem level; vaults with `injection_location` for credentials; `permission_policy` per tool; `allowed_domains`/`blocked_domains` on `web_search`/`web_fetch` (2026-08-19); session budgets. Google has IAM Conditions on both Sessions and Memory Bank, plus Agent Identity. Zep shipped ABAC on 2026-07-09. **"Uniformly" is what fails**: each of these is a per-vendor mechanism, and the whole apparatus is defeated at the semantic layer — a `read_write` store plus prompt injection writes a poisoned memory that later sessions read as trusted, which Anthropic's own docs warn about and [2608.21230](https://arxiv.org/abs/2608.21230) measures as a 55-point accuracy drop with zero screening catch rate.

**(d) Answer "which agent run caused this change" from the changed data itself — PARTIAL AND NEW, and this is the biggest movement since April.**
Anthropic: memory versions are "attributed to the session", and the version list survives memory deletion — so for changes *inside a memory store*, you can answer the question from the store, not from a trace. Google: memory revisions. Zep: facts carry the episode list that produced them, so deletion scope and access filtering are computable from the graph. Research: MemTxn's snapshot journal, MutMem's signed hash-chained transitions, ATP's State-Delta Evidence Ledger, and DBOS's "The Case for Co-Locating Workflow State with Your Data" (2026-06-15) are all attacking exactly this.
**But**: all of it is provenance over *the memory store*, not over the world. Nothing answers "which run edited this file / this row / this ticket, under what permissions, from what context". LangSmith/Braintrust/Weave/Arize and the new OTel GenAI conventions remain **tracing**: an append-only record beside the change, joined by convention, not carried by the changed artifact. The one shipping system where the changed data *is* the versioned artifact is Letta Code's MemFS ("all context, including memory blocks, is tracked via git") — and that is a coding agent's own context, not the user's data.

## 6. WHAT THE APRIL SURVEY MISSED — EVEN AT THE TIME

1. **It surveyed vendors, not the platform.** Claude Managed Agents launched 2026-04-08 and memory stores 2026-04-23 — inside the survey window. A survey of the memory layer that omits the API the models ship behind mistakes the accessory market for the market.
2. **It treated benchmarks as settled.** LoCoMo's retrieval-budget confound and its recall/precision gap were both latent in April; the survey's six systems all quoted LoCoMo numbers, and none of those numbers were budget-controlled.
3. **It had no adversarial axis.** "Context pollution is worse than missing context" was stated as a hygiene problem. It is a security problem: persistent writable memory is a durable injection surface, and the 2026 attack literature (InjecMEM, MAFIA, the poisoning-utility paper) did not exist to correct it.
4. **It missed cost entirely.** No serving-cost figure appears in the prior state. [2608.11879](https://arxiv.org/abs/2608.11879) shows some memory systems never break even against resubmitting the full transcript within 400 turns.
5. **It missed the null hypothesis.** Nobody in the six had shown that competent lexical search over the raw log doesn't match graph structure. [2608.12888](https://arxiv.org/abs/2608.12888) suggests it does.
6. **It framed memory as long-term storage and skipped working context.** The branchable/addressable-context line (ActiveGraph, StateFork, LCM/Volt) and the memory line were the same problem all along; "execution edits" ([2608.22928](https://arxiv.org/abs/2608.22928)) is the join.
