# The 2025–2026 AI Turn in Documentation and Structured Authoring

Grades: **[SWA]** shipped-and-widely-adopted · **[SN]** shipped-niche · **[AO]** announced-only · **[PO]** paper-only · **[OP]** opinion/vendor-marketing.

## 1. "Docs for agents" as an authoring practice

**AGENTS.md is the one genuinely mass-adopted new authoring artifact. [SWA]** It is now "stewarded by the Agentic AI Foundation under the Linux Foundation," originating from OpenAI Codex, Amp, Jules, Cursor and Factory; the site claims "used by over 60k open-source projects" and lists ~22 supporting tools including Copilot, Cursor, Devin, Zed, Gemini CLI, JetBrains Junie, Warp, Semgrep ([agents.md](https://agents.md/), fetched 2026-08-26). My own GitHub code-search counts (2026-08-26, `gh api search/code`, counts are approximate and include forks/non-root files): `filename:AGENTS.md` **845,824**; `filename:CLAUDE.md` **763,904**; `filename:llms.txt` **167,936**; `filename:.vale.ini` **3,832**. Restricting to repo root via `path:/…` returns only double-digit counts, i.e. GitHub's search API caps/serves these inconsistently — treat the magnitudes as ordinal, not exact. The ordering is the finding: agent-instruction files now outnumber docs-linting configs by ~200:1.

Note the tension with your established nulls: adoption is enormous, measured benefit is absent. Nobody has published a positive controlled result for AGENTS.md-style files; the field adopted the artifact on vibes.

**Anthropic Agent Skills / SKILL.md [SWA]** (2025-10-16, [claude.com/blog/skills](https://claude.com/blog/skills)) is the more interesting authoring development because it *is* a structured-authoring spec: a named folder, YAML frontmatter, and explicit **progressive disclosure** (load the name/description first, the body on demand, bundled files last). Adoption claims are testimonial only — Rakuten "a day → an hour", Box "saving hours" — i.e. **[OP]** for the numbers. Docs platforms have since adopted the format as an output target: Mintlify shipped multi-skill support from `.mintlify/skills/` (2026-04-10) and skill install-by-URL (2026-01-30); Read the Docs shipped Read the Docs skills (2026-02-11, [post](https://about.readthedocs.com/blog/2026/02/readthedocs-skills-api-config/)).

**llms.txt is dead as a crawler channel but alive as an agent navigation map — and that distinction is now empirically load-bearing.** Mintlify's benchmark (2026-07-17, [llms-txt-agent-benchmark](https://mintlify.com/blog/llms-txt-agent-benchmark)) ran 2,400 trials — 20 Mintlify sites × 5 questions × 3 repeats × 2 models (Claude Code/Sonnet 5, Codex/GPT-5.5) — across HTML, plain Markdown, Markdown+llms.txt link, and Markdown+inlined llms.txt. Result: **plain Markdown was *worse* than HTML** because agents invented `.md` paths; adding a link to llms.txt produced **~90% fewer dead URLs** and a large token cut, with accuracy flat in the "mid-to-high 90s" across all formats, replicated on Opus 4.8, Fable 5, GPT-5.6. Grade **[SN]** for the result (vendor-run, but pre-registered-style design, open-sourced, and the headline metric is 404s — not a flattering-to-vendor accuracy claim). The mechanism is navigational, matching arXiv 2606.20512: the win is *finding the file*, not the prose.

Platforms kept shipping llms.txt through 2026 regardless: ReadMe custom llms.txt (2026-08-07), Read the Docs llms.txt + llms-full.txt (2026-02-11, [post](https://about.readthedocs.com/blog/2026/02/llms-txt-support/)), Mintlify scoped per-segment indexes at `/_llms/<segment>.md` (2026-08-21). The [llms.txt directory](https://directory.llmstxt.cloud/) lists 3,998 sites — small, and a directory listing is not usage. **[SN]**

**Documentation MCP servers shipped broadly and are the successor channel. [SWA]** Context7 (upstash/context7, 61.2k stars, fetched 2026-08-26) is the widest-used third-party docs-MCP. Mintlify shipped MCP `get_page` (2026-04-03), authenticated permission-scoped MCP (2026-05-08), and **Mintlify Index** (2026-08-06, [post](https://mintlify.com/blog/mintlify-index)) — a public MCP aggregating **9,000 docs sites**, claiming 96/150 blinded task wins vs a competitor, 48% faster, +10% factual correctness, 17% fewer critical errors **[OP/SN — vendor, no released harness]**. GitBook MCP (2026-07-08) lets agents edit and restructure docs. Cloudflare's MCP work is API-side, not docs-side (2026-08-22 changelog); I found no Cloudflare *docs* MCP entry.

## 2. Did tooling change?

Yes, comprehensively, and the axis of change is **serving docs to agents, not authoring them for humans**. Mintlify's 2026 changelog is near-continuous agent work: `assistant.md`/`agent.md` config files (2026-02-20), a **Visibility component that separates human vs agent content** (2026-04-17), agent-feedback beta, Content-Signal robots.txt directives (2026-05-29), "agent score" (2026-05-01), and CLI `mint signup` so an agent can create an account with no browser (2026-08-12) ([changelog](https://mintlify.com/docs/changelog)). GitBook shipped adaptive content branching on `visitor.type` — **serve agents a different page version** (2026-08-14) ([changelog](https://gitbook.com/docs/changelog)). ReadMe shipped AI discoverability (2026-08-03) and MCP server selection (2026-06-12). Docusaurus is the outlier: releases through 3.10.2 (2026-07-10) show **no** llms.txt, copy-as-markdown, or LLM features — only DocSearch v4/AskAI plumbing ([releases](https://github.com/facebook/docusaurus/releases)). **[SWA]** for the commercial platforms; **[SN]** for OSS static-site generators.

**Measured results published by a vendor — the strongest item in this whole report:** Intercom/Fin, "A Causal Inference Approach to Measuring the Impact of Improved RAG Content" (2025-07-07, [fin.ai](https://fin.ai/research/a-causal-inference-approach-to-measuring-the-impact-of-improved-rag-content/)). Matching-based ATET, not A/B: improving knowledge-base content via Fin's Suggestions raised resolution rate by a **weighted average +1.23 percentage points** in month one across ~1,000 customers, with top customers up to +10pp, and only **0.22 correlation between number of approvals and impact** — targeting beats volume; 8 approvals could touch 76% of conversations. **[SWA]** This is the rare case of an organisation restructuring content *and measuring*.

Mintlify's traffic report (2026-07-29, [state-of-docs-traffic](https://mintlify.com/blog/state-of-docs-traffic)) reports agents at **66% of measured traffic**, up from 15.2% in Jan 2026; July 2026: 213M agent requests vs 105M human page loads; **83.7% of agent requests used explicit machine routes**; direct Markdown requests 25.1% (Feb) → 54.4% (July); 1.42M MCP tool calls. **[SN]** — one platform's fleet, self-reported, and "agent" classification is unaudited.

## 3. Linting and doc quality

Essentially **static**. Vale's only 2025–26 release is v3.18.0 (2025-08-20): MDX/Typst/Quarto/MyST parsing, a `meta` scope, CI flags — **no LLM features** ([releases](https://github.com/errata-ai/vale/releases)). [vale.sh/explorer](https://vale.sh/explorer) lists **13 style packages** (Google 36 rules, Microsoft 47, RedHat 37, Elastic 32, Salesforce 28, proselint 34). Spectral's last release is v6.16.3 (2024-08-03) — effectively dormant ([releases](https://github.com/stoplightio/spectral/releases)). Redocly's changelog URL 404s at the path I tried.

**Evidence that linting improves outcomes: I found none.** No study, 2025–26 or earlier, links style-guide conformance to task success, retrieval accuracy, or support deflection. It remains process hygiene **[OP]**.

LLM-as-judge for *docs* specifically is also thin — the technique is ubiquitous for RAG faithfulness but I found no docs-style/readability judge with published human-agreement numbers. Relevant caution: arXiv 2603.12123 (2026-03-12) finds review in a **fresh session with no production history** raises error-detection F1 from 24.6% → 28.6% on technical documents — small, and it exposes how weak LLM doc review is in absolute terms. **[PO]**

## 4. Structure for retrieval — the crux

**Baseline numbers.** Anthropic Contextual Retrieval (2024-09-19, [post](https://www.anthropic.com/news/contextual-retrieval)): top-20 retrieval failure 5.7% → 3.7% (−35%) with contextual embeddings, → 2.9% (−49%) adding contextual BM25, → 1.9% (−67%) with reranking; $1.02/M doc tokens; 800-token chunks, 8k-token docs; recommends skipping RAG under ~200k tokens. Jina late chunking (2024-08-22, [post](https://jina.ai/news/late-chunking-in-long-context-embedding-models/)): nDCG@10 gains that are small and inconsistent — SciFact 64.20→66.10, NFCorpus 23.46→29.98, Quora unchanged; gains scale with document length. RAPTOR (arXiv 2401.18059, 2024-01-31): +20% absolute on QuALITY with GPT-4.

**Chunking sophistication is being systematically debunked.** "Is Semantic Chunking Worth the Computational Cost?" (arXiv 2410.13070, 2024-10-16) found costs unjustified by consistent gains. This replicated through 2026: arXiv 2601.14123 (2026-01-20) — "sentence chunking is the most cost-effective method, matching semantic chunking up to ~5k tokens"; arXiv 2607.01852 (2026-07-02) — cluster-based chunking did not beat simpler strategies. **[PO, multiply replicated]**

**But *structural* signal — as opposed to *semantic* chunk boundaries — does help, and this is the crux answer.** Structure-Aware Semantic Chunking with Title-Chain Prefixes (arXiv 2608.00824, 2026-08-01, Yang Yang; 1,600-query stratified eval over a *production Markdown knowledge base*): prepending the heading hierarchy to each chunk lifted **MRR@5 0.374 → 0.463 (+23.8%)** overall, 0.828 → 0.925 (+11.7%) on answerable queries. Its methodological warning matters more than its headline: in prefix-off ablation, **dual-annotator agreement collapsed from κ=0.45 to κ=0.04** — removing title-chains strips the disambiguating context *annotators* need, so conventional chunking ablations are partly measuring their own labelling protocol. **[PO]** Corroborating: LARAG (arXiv 2605.07517, 2026-05-08) exploits HTML hyperlink structure in technical manuals for better answers with *fewer* chunks — i.e. cross-links are retrieval signal; TelcoAI (arXiv 2601.16984) reports 87% recall with section-aware chunking, +16% over baselines; GraphSkill (arXiv 2603.06620, 2026-02-20) finds top-down traversal of hierarchical doc structure beats flat-text retrieval for code generation.

**The single cleanest "restructuring changes what an LLM can answer" result** is Workflow Cards (arXiv 2608.11022, 2026-08-11, eScience2026, Marchioro et al.): the *same* provenance data re-presented as human-readable structured cards instead of queried via database schema **nearly doubled answer quality**, consistent across LLM-as-judge and human assessment. Content held constant, presentation varied. **[PO]**

**GraphRAG** (Microsoft, arXiv 2404.16130) remains maintained — v3.1.2, 2025-08-21 ([releases](https://github.com/microsoft/graphrag/releases)) — but independent evaluation is deflationary: "Is GraphRAG Needed?" (arXiv 2606.25656, 2026-06-24, Amazon-affiliated authors, nine standardized scenarios) reports a **"retrieval–generation gap where expanded retrieval does not proportionally improve generation quality, suggesting retrieval-oriented metrics overstate advanced retrieval benefits"** — with 19–53% token reduction from plain context engineering. arXiv 2605.20815 (2026-05-20) finds GraphRAG's *local* mode beats *global* summarization on latency and factual grounding, and that the pipeline has a capacity threshold small models cannot clear. **[PO]**

## 5. Long context vs retrieval

Structure still matters, and the 2025–26 evidence is that bigger windows did not dissolve the problem. NoLiMa (arXiv 2502.05167, ICML 2025, v2 2025-07-09): when literal lexical matching is removed, **11 of 13 models fall below 50% of their short-context baseline at 32K**; GPT-4o 99.3% → 69.7%. Chroma's Context Rot (2025-07-14, Hong/Troynikov/Huber, 18 models incl. GPT-4.1, Claude 4, Gemini 2.5, Qwen3, [report](https://www.trychroma.com/research/context-rot)): degradation is non-uniform; a *single* distractor hurts; low needle–question semantic similarity degrades fastest — and, counterintuitively, **models scored better on shuffled haystacks than on logically coherent ones**, which Chroma attributes to structural patterns influencing attention. That last finding is a direct caution against assuming "well-organised long document = better recall." CorpusQA (arXiv 2601.14952, 2026-01-21) reports standard RAG "collapses entirely" at 10M-token corpus scale. LaRA (arXiv 2502.09977, 2025-02-14) finds no universal RAG-vs-long-context winner.

## 6. Did authoring practice change?

Mostly no, at the human/organisational level. **Google Season of Docs concluded after six years (2019–2024)** — "the program has concluded" ([developers.google.com/season-of-docs](https://developers.google.com/season-of-docs)). Write the Docs' 2025–26 blog is entirely conference logistics — **no AI posts, no community survey results** ([writethedocs.org/blog](https://www.writethedocs.org/blog/)). Stack Overflow 2025 Developer Survey (49,000 respondents): 84% using/planning AI tools, 51% of professionals daily, but **46% actively distrust accuracy vs 33% trusting**, and 66% cite "almost right, but not quite" as the top complaint — when AI fails, 75.3% seek *humans*, not docs.

The one organisation reporting a measured content-restructuring result is Intercom (§2). Mintlify's "Docs as an abstraction layer for coding agents" (2026-06-08, [post](https://mintlify.com/blog/structured-docs-coding-agents)) claims **64% more precise, 39% more discoverable, ~50% fewer tokens, 1.5× faster** from ~15 deterministic tasks per repo × 5 runs × 3 conditions (no docs / improved docs / Mintlify docs), verified by exit codes and string matches — but publishes **no baselines, no per-task data, no significance tests**, and promises a benchmark suite "soon." Grade **[OP]** until that lands. It is the most-cited number in this space and it is currently unfalsifiable.
