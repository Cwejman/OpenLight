# Structured authoring & minimalism: evidence report (26 Aug 2026)

**Method note:** the WebSearch budget for this session was already exhausted at 200/200 before I started, so everything below comes from direct fetches of primary sources — GitHub REST API, OpenAlex, Crossref, Semantic Scholar, arXiv API, and vendor/org sites. That biases coverage toward things with APIs and away from trade press. Grades: **[A]** shipped-and-widely-adopted, **[B]** shipped-niche, **[C]** announced-only, **[D]** paper-only, **[E]** opinion.

## TOPIC 1 — DITA, single-sourcing, docs-as-code

### The spec: DITA 2.0 is still not a standard, 10.7 years after 1.3

Hard facts from the TC's own repo, `github.com/oasis-tcs/dita/releases` (fetched 2026-08-26):

- DITA 1.3 approved as OASIS Standard **17 Dec 2015**; Errata 02 **29 Jun 2018**. The last *stable* release artifact is "DITA 1.3 Plus Errata 02", **2 Apr 2024**.
- DITA 2.0 **Beta 01** — 14 Jun 2025. **Beta 02** — 4 Oct 2025. **Beta 03** — **2 Jul 2026**. Still beta. No Committee Specification, no OASIS Standard. **[C]**

The legacy TC page at `oasis-open.org/committees/dita/` still shows 2018 as its most recent announcement and does not mention 2.0 at all — a maintained standards body does not leave its shop window a decade stale.

**Bus factor, measured.** Via `gh api repos/oasis-tcs/dita/commits?sha=DITA-2.0&since=2025-08-26`: 100+ commits in the last 12 months (API page cap), **100% authored by Robert D. Anderson** (appearing under two name spellings), most recent 2026-08-21. The DITA 2.0 specification has, empirically, one committer. **[A — this is a fact about the repo, not an opinion]**

Same measurement on `dita-ot/dita-ot`: 97 commits in 12 months — **Jarno Elovirta 80 (82%)**, Robert D Anderson 8, Roger Sheen 6, three others 1 each.

### The toolkit: genuinely alive, but thin

`api.github.com/repos/dita-ot/dita-ot/releases`: 4.4.1 on **2026-08-21** (five days ago), 4.4 on 2026-01-31, 4.3.5 on 2025-10-21, and a steady 2–5 releases/year back through 2023. DITA-OT 4.4 release notes (dita-ot.org/dev/release-notes/) describe a "preview of features for the upcoming OASIS DITA 2.0 specification" — `<keytext>`, `<linktitle>`, refactored chunking. So: shipping software, current, Java 17+ — but maintained by essentially one person. **[B]**

### The empirical case for reuse/profiling: I could not find one

This is the strongest negative finding in the report. Three OpenAlex full-text searches ("DITA content reuse cost savings technical documentation empirical", "single sourcing structured authoring XML technical communication study", "content reuse translation cost reduction structured content management") returned **no peer-reviewed empirical study of DITA reuse ROI**. What exists is:

- Priestley/IBM-lineage advocacy: "The Darwin Information Typing Architecture (DITA): applications for globalization" (2005), 20 citations — argues reuse "allows for more efficient and reliable localization" with **no measurements**. **[E]**
- Master's theses: "Optimising reuse with DITA XML: A case study of evaluating reuse strategies" (Tampere, 2024, 0 citations); "Case study on XML-Authoring Software" (Theseus, 2018, 0 citations). **[D]**
- The OASIS DITA 1.0 spec itself (2005) has 7 citations.

The entire scholarly footprint of DITA is smaller than that of a mid-tier CS workshop paper.

**Folklore chase — the "30–40% saving" numbers.** I could not trace them to any primary study, and my searches suggest that is because there isn't one. The circulating figures appear to originate in vendor and consultancy ROI calculators and Rockley/Hackos-lineage trade books, which cite each other rather than data. I want to be explicit about the limit of my evidence here: **absence of a source in OpenAlex/Crossref/arXiv is not proof the number is invented** — trade-press and vendor whitepapers are outside those indexes, and my search budget was zero. But the claim "reuse saves 30–40%" is, on this evidence, **[E] opinion presented as measurement**, and anyone citing it should be asked for the N.

The one modern empirical minimalism-plus-DITA study I found is Heinonen et al., "Minimalism for the Win: User-Centered Design for Guidance in Industrial Maintenance," *IEEE Trans. Prof. Comm.*, Dec 2022, DOI 10.1109/TPC.2022.3205468 — explicitly self-described as **exploratory**, using participant observation, interviews and questionnaires with maintenance personnel in three countries. No effect sizes, no control condition. 3 citations. **[D]**

### Markdown vs XML for LLMs

There is no evidence base for "XML is better for LLM retrieval." Three arXiv API queries surfaced only:

- **"The Format Tax"** (arXiv:2604.03616, 2026-04-04): structured output requirements — **JSON, XML, LaTeX, Markdown** — *substantially degrade* reasoning and writing performance across open-weight models, with the dominant cost entering **at the prompt**, not at decoding. This cuts against markup-heavy prompting generally. Note it is about *output* format. **[D]**
- "XML Prompting as Grammar-Constrained Interaction" (arXiv:2509.08182, 2025-09-09): a theory paper — fixed-point semantics, convergence guarantees — **no empirical retrieval comparison**. **[D]**
- "ObjectGraph: ...A Native File Format for the Agentic Era" (arXiv:2604.27820, 2026-04-30) argues *every existing document format*, XML included, is wrong for agents. **[D]**

The tcworld "DITA is AI-ready" argument has, so far as I can establish, **zero supporting measurement**.

## TOPIC 2 — Minimalism (Carroll)

### The original studies

- **Carroll & Carrithers, "Training wheels in a user interface," CACM (1984)** — abstract confirms: a training interface for a commercial word processor made error states unreachable; produced "substantially faster learning," better learning achievement, better comprehension post-test; the **control group spent almost a quarter of their time recovering from blocked error states**. Note this paper carries **1 citation in OpenAlex** (indexing artifact — the companion below carries the load).
- **Carroll & Carrithers, "Blocking Learner Error States in a Training-Wheels System," *Human Factors* (1984)**, 132 citations — "improved learning efficiency in **two experiments**, one learning-by-doing, one learning-by-the-book."
- **Carroll, *The Nurnberg Funnel* (MIT Press, 1990)** — 649 citations; **"Minimalism Beyond the Nurnberg Funnel" (1998)** — 118.
- Independent partial replication: Vora & Helander, "Designing minimal documentation using a GOMS model" (1990, 60 citations) — modified a manual for reduced verbiage, real-task focus, and error recovery; found **"significant improvements in learning performance"** in novice evaluation.

**All of it is 1980s–early-90s office word processors, with participants who were computer novices in a sense that no longer exists.** That is the single most important caveat in this report.

### Did it replicate — and what the successor actually said

Hans van der Meij (Twente) is the empirical successor: OpenAlex author A5035876797, **207 works, 2,850 citations**. His verdict in 1992 is the load-bearing quote, from the abstract of "A critical assessment of the minimalist approach to documentation" (SIGDOC '92, DOI 10.1145/147001.147003, 27 citations):

> "it is not very clear what minimalism really means… **It is also not yet settled that a minimalist approach is the most effective one because critical experiments have hardly been conducted.**"

He then ran them: van der Meij & Lazonder, **"The minimal manual: is less really more?"** *Int. J. Man-Machine Studies* (Nov 1993, DOI 10.1006/imms.1993.1081, 48 cites) and "Assessment of the minimalist approach to computer user documentation," *Interacting with Computers* (Dec 1993, DOI 10.1016/0953-5438(93)90001-a, 17 cites). The canonical practitioner artifact is **van der Meij & Carroll, "Principles and Heuristics for Designing Minimalist Instruction"** — the 1998 MIT Press chapter version is his single most-cited minimalism work at **150 citations**; the 1996 IEEE TPC "Ten misconceptions about minimalism" has 32.

**The line stops.** Filtering his 207 works for "minimal" in title/abstract returns **13 items, the last substantive one in 2003–04** ("Minimalism revisited," *Document Design*, 10 cites; "Recent research on minimalism," 2004, 0 cites), plus one 2020 review of error-inclusive approaches (3 cites). Everything he has published since 2019 — 10 works — is about **instructional video, embedded questions in recorded lectures, practice schedules, serious games, and early-childhood storytelling**. His live doc-adjacent output is the video-tutorial line: "Eight guidelines for the design of instructional videos for software training" (2013, 82 cites) → "**Eleven** Guidelines…" (2022, 16 cites), and "A comparison of paper-based and video tutorials for software learning," *Computers & Education* (2014, 131 cites).

That is the honest picture: minimalism was **partially and favourably replicated in the early 1990s by its main critic**, on the same 1990s software-learning tasks, and then the researcher moved on. I found **no meta-analysis and no failed replication**. **[D — real evidence, narrow, old, small]**

### Is the modern citation load-bearing?

No. I checked the most influential contemporary docs framework directly: **diataxis.fr/foundations/ cites nothing** — not Carroll, not minimalism, not DITA, not information typing. It presents its two-axis derivation as original analysis. So Diátaxis's concept/task/reference-shaped quadrants share DITA's topic types by convergence-or-silence, not by acknowledged descent. Where minimalism *is* cited in practice, it is typically ceremonial. **[E]**

One live thread worth knowing: the strongest modern critique adjacent to minimalism is **Kirschner, Sweller & Clark, "Why Minimal Guidance During Instruction Does Not Work," *Educational Psychologist* (2006), 6,813 citations** — vastly more cited than anything Carroll wrote. It targets constructivist/discovery learning, not Carroll's minimalism specifically, but anyone invoking "minimal instruction" as settled science is walking into it.

### The one-line synthesis

The structured-authoring lineage is **not dying — it is calcifying**: shipping toolkit, active vendors, a decade-late spec written by one person, and an evidence base that, on the indexes I can reach, does not exist. Minimalism is the opposite shape: **real, replicated, small, and thirty years old**, cited today mostly as heraldry by frameworks that don't cite it at all.
