## Verdict

Yes — consolidation has happened, and it happened inside MCP. **MCP Apps (SEP-1865)** is now the official UI extension to the Model Context Protocol, and the two prior contenders (OpenAI Apps SDK, MCP-UI) have both folded into it. A separate, non-competing **structured** standard (OpenUI Lang) is growing fast in the app-developer layer. All figures below are from primary API/text reads on **2026-08-26**; npm download windows are 2026-07-26 → 2026-08-24.

## State of play

**MCP Apps / `modelcontextprotocol/ext-apps` — shipped-and-adopted; the winner.** SEP-1865, "MCP Apps: Interactive User Interfaces for MCP," Track: Extensions, **Status: Stable (2026-01-26)**, created 2025-11-21. Authors are cross-vendor: Ido Salomon and Liad Yosef (MCP-UI), Olivier Chafik, Jerome Swannack, Jonathan Hefner, Anton Pidkuiko, Nick Cooper, Bryan Ashley, Alexi Christakis. Extension identifier `io.modelcontextprotocol/ui`. Contract: server predeclares a resource under a `ui://` URI with mimeType **`text/html;profile=mcp-app`**; a tool links to it via **`_meta.ui.resourceUri`** (the flat `_meta["ui/resourceUri"]` form is already deprecated "before GA"); the host renders it in a mandatory sandboxed iframe and talks to it over JSON-RPC across postMessage — `ui/initialize` → `ui/notifications/initialized`, then `ui/notifications/tool-input`, `ui/notifications/tool-input-partial`, `ui/notifications/tool-result`; View→Host requests `ui/open-link`, `ui/message`, `ui/request-display-mode` (`inline|fullscreen|pip`), `ui/update-model-context`. Security is declarative: `_meta.ui.csp` with `connectDomains` / `resourceDomains` / `frameDomains` / `baseUriDomains`, plus `permissions` (camera, microphone, geolocation, clipboardWrite). Theming ships standardized CSS variables. The spec's own motivation section names the merger explicitly: MCP-UI "developed the bi-directional communication model" and the Apps SDK "further validated the demand"; this SEP "unifies the approaches pioneered by MCP-UI and the Apps SDK into a single, open standard." Adoption: repo 2,762 stars, pushed 2026-08-12; npm `@modelcontextprotocol/ext-apps` v1.7.5 (2026-07-23), first published 2025-12-08, **12,177,761 downloads/month**. The official client matrix lists 11 hosts with MCP Apps support: Claude (web), Claude Desktop, VS Code GitHub Copilot, **Microsoft 365 Copilot**, Goose, Postman, MCPJam, **ChatGPT**, Cursor, Archestra.AI, PostHog Code. Draft revision adds "App-Provided Tools" (guest UI registers tools back to the host) and a section on its relation to WebMCP.

**OpenAI Apps SDK — shipped-and-adopted, but subordinated.** OpenAI's own docs now say: *"ChatGPT implements the open MCP Apps standard for UI returned by an MCP server."* Guidance is to declare UI via `_meta.ui.resourceUri` and use the `ui/*` bridge first; `_meta["openai/outputTemplate"]` and the `window.openai` bridge (`toolInput`, `toolOutput`, `callTool`, `sendFollowUpMessage`, `widgetState`/`setWidgetState`, `uploadFile`, `requestModal`, `requestCheckout`) survive as **compatibility aliases** plus ChatGPT-only extensions. No props schema — components receive data over the notification bridge. `openai/openai-apps-sdk-examples`: 2,318 stars, last pushed 2026-04-15 (stale). A directory and submission/review process exist but I **could not verify** GA wording, launch dates, or which partner apps have shipped — that page is navigation-only.

**MCP-UI — absorbed, now an SDK not a standard.** Repo moved `idosal/mcp-ui` → **`MCP-UI-Org/mcp-ui`** (5,103 stars, pushed 2026-07-08). README: *"The `@mcp-ui/*` packages implement the MCP Apps standard."* `@mcp-ui/client` v7.1.1 (2026-05-09), 1,200,073 dl/mo; `@mcp-ui/server` v6.1.0 — last published **2026-02-13**, 595,033 dl/mo. Its `rawHtml`/`externalUrl`/`remoteDom` triad is now "legacy MCP-UI hosts" behind `AppRenderer`.

**AG-UI — shipped-and-adopted, different layer.** 15,553 stars, pushed 2026-08-26; `@ag-ui/core` 0.0.58 (2026-08-14), **6,076,900 dl/mo**; `@copilotkit/react-core` 1,591,915 dl/mo. Confirmed **event-stream oriented, not component oriented**: lifecycle, text, tool-call, `StateSnapshot`/`StateDelta`, activity, reasoning, subagent, `Raw`/`Custom`. Docs contain **no UI-rendering events**. It is a transport, and OpenUI streams over it.

**Vercel AI SDK — the retreat is real.** `ai` v7.0.79 (2026-08-25), 86,429,654 dl/mo. But RSC generative UI is explicitly demoted: docs carry a warning — *"AI SDK RSC is currently experimental. We recommend using AI SDK UI for production"* — with a `migrating-to-ui` guide. `@ai-sdk/rsc` is only 341,076 dl/mo, ~0.4% of `ai`. Grade: **shipped-niche / de-emphasised**.

**Thesys — pivoted and renamed.** `thesysdev/crayon` now redirects to **`thesysdev/openui`**, "The Open Standard for Generative UI," 8,459 stars, pushed 2026-08-26, MIT. Core is **OpenUI Lang**, a compact streaming DSL (`root = Stack([header, content])`) parsed into a typed element tree validated against a JSON schema generated from *your* component library; the same library generates the system prompt. Renderers for React/Vue/Svelte/email/browser-bundle. `@openuidev/lang-core` created **2026-03-25**, already **413,615 dl/mo**; react-lang 394,419; react-ui 142,886. Official integrations: assistant-ui, Lynx, LangChain/LangGraph, Mastra; named adopters include Productboard, Standard Metrics, Oodle. Legacy `@crayonai/react-core` 28,687 dl/mo and `@thesysai/genui-sdk` 14,835 dl/mo are the vestigial commercial line. Grade: **shipped-niche, steep ramp**. Governance is still a single vendor's GitHub org — no foundation; "open standard" is a claim, not yet a governance fact.

**Google / Microsoft JSON-UI:** no UI extension exists in the `a2aproject` org (only `experimental-ext-oid4vp-auth`); Microsoft's answer is M365 Copilot implementing MCP Apps. Core MCP 2026-07-28 has **no UI in the base spec** — UI lives only in the extension, and elicitation was in fact *simplified* (MRTR replaced server-initiated elicitation).

## Opaque vs structured

The consolidated standard is **opaque**: an HTML/JS blob in a sandboxed iframe, props-less, data arriving via notifications, security handled by declarative CSP rather than by type. That is what every major host implements. Structured — a typed component tree the host renders with *its own* components — lost at the protocol layer and is thriving one layer up (OpenUI Lang, assistant-ui, Lynx), where the app owns both model and renderer. The split is stable because the two solve different problems: iframes give cross-host portability without design agreement; typed trees give design-system fidelity but require host and server to share a component vocabulary. Note the escape hatch: `@openuidev/browser-bundle` ships the renderer "as script + stylesheet assets" for "CDN, iframe, and no-build embeds" — i.e. a structured tree can be smuggled inside an MCP Apps iframe.

## Implications

A project whose interface is **already typed data** is advantaged, not commoditised. The opaque standard makes an HTML bundle the transport unit but says nothing about how you author it — typed data is exactly what you need to render either into a `ui://` bundle *or* into a host's own components (OpenUI Lang, assistant-ui) without rewriting. The commoditised asset is the hand-written iframe widget; the durable asset is the typed model plus a small renderer per target. Ship the typed layer, emit MCP Apps as one adapter.
