## (a) What is actually established

**1. Generic repository context files do not reliably improve agent task success.** Two independent studies converge on this null. Gloaguen, Mündler, Müller, Raychev & Vechev, *Evaluating AGENTS.md* ([arXiv:2602.11988](https://arxiv.org/abs/2602.11988), Feb 2026, rev. Jun 2026) tested two settings — SWE-bench tasks with LLM-generated context files, and a novel corpus of issues from repos with developer-committed context files — across multiple LLMs and agents. Verified verbatim: "providing context files does not generally improve task success rates, while increasing inference cost by over 20% on average." They single out the specific practice vendors recommend most: repository overviews were unhelpful. The abstract does not state task counts; I could not verify N.

Khatri, *Do Context Files Help Coding Agents?* ([arXiv:2607.27250](https://arxiv.org/abs/2607.27250), Jul 2026) is a cleaner ablation: 2 frontier agents (Claude Code, Codex), 17 tasks / 3 repos, **288 evaluated runs**, gold-test evaluation. Verified verbatim: "Context strategy does not measurably move correctness on either agent (bounded to <=10-15pp via equivalence testing)." The failure-mode triage is the load-bearing part — agents fail on "implementation skill---feature design, pattern selection, exact wiring---not missing repository knowledge that a context file could supply," and a manipulation probe confirmed the real AGENTS.md "never converts a near-miss to a pass." Grade: two single-studies, different designs, agreeing on the null → the strongest claim in this literature.

**2. But targeted, empirically-tuned guidance does help — through localisation, not comprehension.** Shepard & Albrecht, *Probe-and-Refine Tuning of Repository Guidance* ([arXiv:2606.20512](https://arxiv.org/abs/2606.20512), Jun 2026), SWE-bench Verified, Qwen3.5-35B-A3B, 4 trials: **33.0% mean resolve (refined) vs 28.3% (static knowledge base) vs 25.5% (unguided)**. Critically, the gain came from agents reaching the correct files (+14.5pp coverage) while patch quality stayed flat (~59%). This reconciles with #1: prose *explanation* is inert, *navigational pointers* are not.

**3. Code beats prose as context — pre-registered, with a published null.** Sam-Bodden, *What Context Does a Coding Agent Actually Need to Act?* ([arXiv:2607.09691](https://arxiv.org/abs/2607.09691), Jun 2026) holds localisation fixed with an oracle and varies only representation, scored on SWE-bench Verified. Verified verbatim: natural-language summaries "answer almost none of the behavioral questions that the source answers (**4/45 vs. 27/45**, held-out repositories, independent judge), and the gap belongs to the representation, not the summarizer — a frontier model's summaries score exactly as poorly as a 3B model's." Their registered hypothesis *failed*: rendering a file's remainder as UML skeletons/signatures "resolves no more issues than deleting that remainder outright (**N=70, exact McNemar p=0.75**)." Compressed context matched whole files at a third of the tokens (19K vs 94K per resolved issue).

**4. A noise floor that invalidates much of the surrounding literature.** Same paper, verified verbatim: "temperature-0 API inference flips ~**9% of per-instance outcomes** between byte-identical runs. That is a noise floor under every small effect reported on this benchmark, including ours." Any single-run SWE-bench ablation claiming a few points of improvement from documentation is likely unfalsifiable. This is the single most useful methodological fact I found.

**5. Agents are genuinely weak at repository structural reasoning.** *RepoMirage* ([arXiv:2605.26177](https://arxiv.org/abs/2605.26177), May 2026) applies semantics-preserving repo perturbations; reported drop from 66.8% to 25.3% when agents must explicitly identify structural information. *Number not verified against primary text* — from a single fetch summary only.

## (b) Asserted but unmeasured

**A large descriptive literature, a tiny effects literature.** Corpus-characterisation studies vastly outnumber outcome studies and none of them measure whether the files work: *Agent READMEs* ([arXiv:2511.12884](https://arxiv.org/abs/2511.12884), Nov 2025, rev. Aug 2026) — 2,303 context files from 1,925 repos, testing 75.9% / implementation 70.8% / architecture 68.1%, security 14.8% / performance 14.5%; and *A Study of Cursorrules Files* ([arXiv:2608.10622](https://arxiv.org/abs/2608.10622), Aug 2026) — 12,110 `.cursorrules` files from 11,427 repos, verified verbatim, purely descriptive, and notably finding adoption "concentrated in small-scale, low-activity, single-maintainer repositories, suggesting toy projects rather than professional development."

**A direct contradiction on cost.** 2602.11988 reports context files *raise* inference cost >20%. Lulla, Mohsenimofidi, Galster, Zhang, Baltes & Treude ([arXiv:2601.20404](https://arxiv.org/abs/2601.20404), Jan 2026), 10 repos / 124 PRs, verified verbatim, report AGENTS.md "associated with a lower median runtime (Δ 28.64%) and reduced output token consumption (Δ 16.58%)." Plausibly reconcilable (input tokens up, output flailing down) but nobody has done it; note 2601.20404 is a 5-page paper using associational language.

**llms.txt has essentially no evidence base.** I found no adoption-or-effect study for llms.txt in a code/repo setting. The only measurement-flavoured hit was a non-code RAG experiment (arXiv:2603.10700, +29.6% claimed) which I did **not** verify. Treat llms.txt as vendor-advocacy-grade.

**Normative "smell" catalogues without outcomes.** arXiv:2606.15828 (configuration smells: Lint Leakage 62%, Context Bloat 42%, Skill Leakage 35%) and arXiv:2606.09090 (stale references in 23.0% of repos) — both *unverified by me*, and neither ties a smell to a measured success delta.

**Industry/vendor evals: not covered.** My WebSearch budget was exhausted at the outset, so I could not check Aider leaderboards, METR, Cognition, or SWE-bench-maintainer posts. I have no verified vendor benchmark to report and will not guess at one.

## (c) Human-vs-model divergence

The evidence says **converge on navigation, diverge on explanation**.

Divergence: 2607.09691's 4/45-vs-27/45 result is the sharpest datapoint — natural-language summaries, the canonical human-oriented artifact, carry almost no actionable signal for an agent at the edit site, and this is a property of the *representation*, not summary quality (frontier and 3B summarisers scored identically).

Le, Nguyen & Nguyen, *Do Machines Struggle Where Humans Do?* ([arXiv:2606.31725](https://arxiv.org/abs/2606.31725), Jun 2026) builds directly on a prior human obfuscation study, using the Block Model across five obfuscation tiers. Verified verbatim: "reasoning-tuned models demonstrate significant alignment with human difficulty patterns across experience levels, whereas instruction and coder-tuned models show **near-zero correlation**." So convergence is *model-class-dependent* — not a stable property of "LLMs." Exact human N is not in the abstract; unverified.

Rong, Sefidi Esfahani, Yadavally, Rigby & Nguyen ([arXiv:2608.00624](https://arxiv.org/abs/2608.00624), Aug 2026) is a clean negative: token perplexity does not reliably correlate with human understandability judgments across multiple human-grounded datasets; distributions are skewed by non-semantic tokens, human labels show low consensus, and results swing by model and tokenizer. So no shared readability metric is currently available. (Correlations not in the abstract; unverified.)

Convergence: 2606.20512's mechanism — guidance helps by getting the agent to the right files, not by improving the patch — is exactly what a good README's orientation section does for a new human contributor. Both audiences benefit from *where things live, how to run tests, which conventions are non-inferable*; only humans benefit from *what the code means*.

## (d) Ten leads

1. [arXiv:2602.11988](https://arxiv.org/abs/2602.11988) — ETH/SRI group; the central null result on AGENTS.md across two settings.
2. [arXiv:2607.27250](https://arxiv.org/abs/2607.27250) — 288-run two-agent ablation with equivalence testing and failure-mode triage.
3. [arXiv:2607.09691](https://arxiv.org/abs/2607.09691) — pre-registered representation ablation; prose-vs-source, plus the ~9% temperature-0 noise floor.
4. [arXiv:2606.20512](https://arxiv.org/abs/2606.20512) — the one positive result, isolating localisation as the mechanism.
5. [arXiv:2601.20404](https://arxiv.org/abs/2601.20404) — 124-PR efficiency study; contradicts #1 on cost direction.
6. [arXiv:2606.31725](https://arxiv.org/abs/2606.31725) — human-vs-LLM comprehension on the same obfuscation corpus.
